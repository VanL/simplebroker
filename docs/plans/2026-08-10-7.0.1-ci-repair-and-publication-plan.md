## Invariants and Boundaries

- Production queue, transaction, permission, CLI, and storage behavior does not
  change.
- The evidence test must collect real extension test modules without requiring
  the extension packages to be installed into the core test environment.
- The transaction test must continue to detect the forbidden lock ordering via
  its non-blocking operation-lock probe. Increasing only the unrelated
  admission deadline must not weaken that oracle. The admission budget is
  scaled from 30 seconds, strictly greater than every coordination wait scaled
  from 10 seconds.
- No tag is created until required workflows are green for the exact repair
  SHA. Existing release tags are never moved or force-pushed.
- PyPI publication is irreversible. A transient tagged-but-unpublished workflow
  failure may rerun for the same unmoved tag/SHA. A product defect after tag,
  or any completed PyPI publication, requires a new version; 7.0.1 is never
  moved or rewritten.

## Implementation

1. Prepend both extension source roots to the evidence collector subprocess
   `PYTHONPATH`, preserving any inherited path. Verify in a deliberately
   isolated core-only environment with extension runtime dependencies but
   without installed extension distributions.
2. Scale the transaction-admission test budget for CI while retaining the
   immediate non-blocking lock oracle. Repeat the focused test under `CI=1`.
3. Run focused tests, full core/PostgreSQL/Redis gates, lint, format, typing,
   documentation gates, and an independent review. Commit and push the repair.
4. Run `python bin/release.py --version 7.0.1` from a clean `main`. The
   driver must reuse the unpublished version, wait for exact-SHA required
   workflows, then create and push `v7.0.1`.
5. Monitor the tag-triggered release gate until PyPI and GitHub Release both
   report 7.0.1. Verify a clean isolated install reports version 7.0.1 and
   performs a real write/read round trip.

## Stop Gates and Rollback

- Stop before commit if either fix requires production code or a dependency
  change.
- Stop before tag if any required exact-SHA workflow fails or `origin/main`
  no longer contains the tested repair SHA.
- Before tag, rollback reverts every repair or generated release commit created
  by this run.
- If an immutable tag exists but its release gate fails before publication,
  rerun that workflow for the same unmoved tag and SHA after diagnosing the
  transient. Never move the tag.
- A product defect or any completed PyPI publication requires a new corrective
  version. Repository code may still be reverted, but the tag and published
  artifact cannot.

## Out of Scope

- Production queue, locking, storage, permission, or CLI changes.
- Moving or recreating release tags.
- Publishing PostgreSQL or Redis extension versions.
- Repairing the unrelated editable sibling Weft checkout.
- Refactoring the release driver or CI topology.
